# Audit RuangSinyal - 14 September 2026

## Cakupan

Pemeriksaan source frontend dan backend, seluruh tes Go, TypeScript, lint,
alur sesi, validasi identitas sosial, callback Apple, dan perubahan status order.
Pemeriksaan browser publik dilakukan pada lebar 320, 390, dan 1365 piksel.
Tidak ada pembelian, pengiriman ke provider, perubahan saldo, migrasi database,
atau pengujian pengambilalihan terhadap akun pengguna produksi.

## Perbaikan

Prioritas tertinggi juga ditemukan di deployment: pemanggilan otomatis SQL reset
katalog dan penambahan saldo dummy telah dihapus dari `deploy-prod-release.sh`.
File SQL tetap tersedia untuk operasi manual yang secara khusus disetujui.
Tidak ada upaya menjalankan atau membalikkan operasi data itu selama audit.

1. Login Apple: audience wajib sesuai konfigurasi aplikasi, algoritma wajib RS256,
   subject dan masa berlaku diperiksa, email hanya boleh berasal dari klaim
   terverifikasi dan tidak boleh berbeda dari email permintaan.
2. Notifikasi Apple: tanda tangan dan klaim diverifikasi sebelum penonaktifan akun.
   Event dibaca dari `events`, termasuk format JSON-string, dan kegagalan database
   tidak lagi dilaporkan sebagai keberhasilan.
3. Middleware JWT API: status aktif dan peran dibaca ulang dari database agar token
   lama tidak mempertahankan hak akses akun nonaktif atau peran yang telah berubah.
4. Sesi frontend: cookie tidak lagi dipercaya hanya berdasarkan decode JWT.
   Identitas aktif harus dikonfirmasi backend; respons divalidasi dan tidak di-cache
   antar-request. Identitas server dipakai untuk nama, email, dan peran.
5. Status order: pembacaan status dan pembaruan dilakukan dalam transaksi dengan
   `FOR UPDATE`, sehingga callback bersamaan tidak menimpa status final berdasarkan
   pembacaan lama. Kebijakan transisi status yang sudah ada tetap dipertahankan.
6. Endpoint login: JSON null/tipe salah ditolak dengan 400, kegagalan backend menjadi
   503, pembatasan percobaan tetap 429. Pesan UI tidak menyalahkan password ketika
   layanan login sedang tidak tersedia. Penyimpanan sesi juga menangani JSON null.

## Tes regresi

- Identitas Apple dengan audience lain, issuer salah, token kedaluwarsa, algoritma
  salah, subject kosong, email berbeda, dan email tidak terverifikasi.
- Notifikasi dengan tanda tangan palsu dan notifikasi deactivation yang tidak sah.
- Akun nonaktif, penurunan peran, dan gangguan database pada middleware autentikasi.
- Dua pembaruan status bersamaan, rollback saat write gagal, serta order tidak ada.
- Identitas frontend invalid/nonaktif dan endpoint login dengan input/upstream buruk.

## Batas dan tindak lanjut

Hasil verifikasi: seluruh `go test -count=1 ./...` dan `go vet ./...` lolos;
TypeScript, lint, serta 8 tes frontend lolos. Tes race Linux pada package helper,
service, repository, controller, dan scripts juga lolos. Build produksi frontend
dan backend berhasil, kemudian diaktifkan sebagai `build-audit-20260914163739`
tanpa migrasi database. Pemeriksaan browser lokal memastikan cookie palsu tidak
membuka halaman akun. Commit/push GitHub masih memerlukan persetujuan pengguna.

- Ini bukan jaminan seluruh aplikasi bebas bug atau sertifikasi keamanan.
- Tes order menggunakan driver database simulasi. Uji integrasi PostgreSQL dan
  provider sandbox masih diperlukan untuk seluruh variasi pembayaran/refund.
- Alur dashboard per peran, transaksi berbayar, refund nyata, dan login OAuth sampai
  selesai memerlukan akun uji serta lingkungan staging khusus.
- Token pada route retail yang melakukan parsing autentikasi sendiri tetap memerlukan
  audit lanjutan per service; perubahan middleware berlaku pada route yang memakainya.
- Login Google tetap bergantung pada konfigurasi callback di Google Console.
- Apple ditolak bila audience aplikasi belum dikonfigurasi; Google tidak terpengaruh.
